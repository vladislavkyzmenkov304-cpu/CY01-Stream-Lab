# Physical test: CY01 Stream Lab v0.1

Device-side observations from the first physical CY01 + Android test.

## Confirmed

- BLE connection to the HeyCyan service works from the standalone lab app.
- Battery query `0x42` returned a valid live response (100% in this run).
- Capability query `0x47` again reported `supportLiveReview=false`.
- Preview P2P start `[02 01 14 01]` was accepted by the glasses and produced a structured `0x41` response.
- The preview response used the same general credential-carrying shape already observed for Wi-Fi transfer control replies: command echo, two little-endian length fields, then ASCII SSID/password material.
- Stop preview `[02 01 15 01]` produced a `0x41` response.

## Timing finding

In v0.1 the Android app called `WifiP2pManager.discoverPeers()` about 0.97 s after sending preview start. Android returned reason `2` (`BUSY`). The glasses' preview ACK arrived about 0.50 s later, roughly 1.47 s after the BLE command.

This means the v0.1 Android P2P discovery attempt was made before the glasses had completed the preview/Wi-Fi setup sequence.

## v0.2 change

v0.2 no longer starts P2P discovery on a fixed 900 ms timer. It waits for the `0x14` preview ACK, then starts discovery after a short settling delay. If Android still reports `BUSY`, discovery is retried with bounded delays. A fallback timer remains for cases where the ACK is not observed.

No firmware flashing, OTA, reset, restart, or unknown BLE command brute force is used.
