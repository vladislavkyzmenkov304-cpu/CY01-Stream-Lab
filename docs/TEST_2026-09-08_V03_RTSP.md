# Physical test: v0.3 RTSP breakthrough

Date: 2026-09-08

## Hardware result

A physical CY01 + Android 16 test completed the full local control path:

1. BLE preview start `[02 01 14 01]` was acknowledged.
2. The glasses returned structured preview Wi-Fi data.
3. Android Wi-Fi Direct discovery succeeded after the preview ACK.
4. The CY01 peer was found and a P2P group formed.
5. The phone became group owner on `p2p0` with local IPv4 `192.168.49.1`.
6. BLE P2P IP query `[02 03]` returned the glasses address `192.168.49.96`.
7. Ordinary sockets routed correctly over the local P2P interface.

Unique device identifiers and the preview password are intentionally omitted from this public record.

## Service classification in preview mode

At `192.168.49.96` during the active preview session:

- TCP/80: connection refused.
- TCP/554: connection refused.
- TCP/8554: accepts connections.

RTSP `OPTIONS` requests on port 8554 returned `RTSP/1.0 200 OK` for all current candidate paths:

- `/testH264VideoStreamer`
- `/xxx.mov`
- `/h264`
- `/live`
- `/stream`
- `/`

This proves that the physical CY01 exposes an RTSP control service on port 8554 after the HeyCyan preview command. It does **not** yet prove that every candidate path contains video, because `OPTIONS` can be answered independently of resource validity.

## Next proof boundary

The next test must cross the media boundary rather than only the RTSP control boundary:

`DESCRIBE -> SDP -> SETUP -> PLAY -> RTP -> decoded video frame`

v0.4 therefore adds a Media3 RTSP player, forces RTP-over-RTSP/TCP, probes candidate paths with `DESCRIBE`, and attempts local decoding on the phone. A rendered first video frame will be treated as definitive proof of live camera video from CY01.

## Safety

Preview remains bounded by an automatic stop timer and the app sends the known preview-stop command before removing the Wi-Fi Direct group.
